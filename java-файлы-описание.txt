JAVA-ФАЙЛЫ ПРОЕКТА GameAI И ИХ НАЗНАЧЕНИЕ
=========================================

Актуализировано: 23.11.2026 по текущим исходникам и подтверждённым запускам.
Всего файлов: 9
Корень исходников: GameAI\src\main\java\


1. Main\Main.java
-----------------
Точка входа в программу, главный класс игры.
Наследуется от SimpleApplication (jMonkeyEngine).
- Создаёт окно игры и базовую сцену: серый пол 40x40 м, камера,
  направленный и рассеянный свет (свет нужен будущим glTF-моделям из Blender).
- Выбирает реализацию нейросети: по умолчанию MockLocalLlm (заглушка),
  реальная Phi включается флагом -Dgameai.llm=onnx.
- Загружает модель в отдельном фоновом потоке (llmExecutor),
  чтобы не тормозить render-поток.
- Обрабатывает клавиши:
  1 — запрос режима выживания,
  2 — запрос режима сбора предметов.
- Запускает генерацию режима асинхронно (CompletableFuture),
  а применение режима к сцене возвращает в render-поток через enqueue().
- При закрытии освобождает ресурсы модели и останавливает фоновый поток.
- Блокирует повторную генерацию через generating и сбрасывает флаг
  как после успеха, так и после ошибки.
- Измеряет loadMs и полный generationMs через System.nanoTime().
- setPauseOnLostFocus(false) отключает паузу jME при потере фокуса.
- Произвольный ввод через NPC и HUD пока отсутствуют: 1/2 — отладочные запросы.


2. LLM\LocalLlmClient.java
--------------------------
Интерфейс (общий контракт) для клиентов локальной нейросети.
Его реализуют MockLocalLlm и OnnxGenAiPhiClient, поэтому весь остальной
код не зависит от того, работаем мы с заглушкой или с реальной моделью.
Методы:
- load() — загрузить модель в память (в фоновом потоке);
- generate(prompt) — получить сырой текст ответа модели;
- isReady() — готова ли модель к генерации;
- close() — освободить ресурсы (интерфейс расширяет AutoCloseable).


3. LLM\MockLocalLlm.java
------------------------
Заглушка нейросети: реализует LocalLlmClient, но никакой модели не запускает.
- load() мгновенно выставляет флаг готовности.
- generate() всегда возвращает один и тот же готовый валидный JSON
  тестового режима (ночь, туман, 3 врага, 2 предмета, выжить 60 секунд).
Нужна для разработки и отладки игры без тяжёлой ONNX-модели.


4. LLM\OnnxGenAiPhiClient.java
------------------------------
Реальный клиент локальной нейросети Phi-3.5-mini через ONNX Runtime GenAI.
- load() проверяет каталог модели и наличие genai_config.json,
  загружает модель и токенизатор в память (один раз, потом переиспользуются).
- generate() токенизирует промпт, генерирует ответ токен за токеном
  и собирает текст через TokenizerStream.
- Настройки генерации: maxNewTokens = 768 (JSON-спеке хватает с запасом),
  temperature = 0 (детерминированная генерация — важно для строгого JSON).
- Есть расширенная версия generate() с собственным лимитом токенов
  и колбэком для потокового вывода кусочков текста.
- cleanup() вырезает из ответа служебные токены чат-шаблона
  (<|end|>, <|assistant|> и т.п.).
- close() освобождает нативные ресурсы модели и токенизатора.


5. LLM\llmtest\OnnxSmokeTest.java
---------------------------------
Отдельный тестовый запускаемый класс (main) для проверки ONNX-клиента
без запуска игры.
- Загружает реальную модель Phi по пути из флага -Dphi.model.dir
  (или по пути по умолчанию).
- Отправляет простой чат-промпт в формате Phi-3.5 и печатает ответ в консоль.
Это smoke-тест: быстро проверить, что модель вообще загружается и отвечает.
В игровой логике не участвует.


6. LLM\GameMode\GameModeSpec.java
---------------------------------
Модель данных: строгая спецификация игрового режима (то, что LLM
имеет право вернуть в виде JSON). Jackson заполняет эти поля при парсинге.
Содержит:
- константы со списками допустимых значений: SUPPORTED_TIMES (day/night/sunset),
  SUPPORTED_WEATHERS (clear/rain/fog), SUPPORTED_OBJECTIVE_TYPES,
  SUPPORTED_SPAWN_TYPES, SUPPORTED_EVENTS, SUPPORTED_ACTIONS;
- поля: schemaVersion, name, description, difficulty;
- вложенные классы: World (гравитация, время суток, погода),
  Player (скорость, прыжок, здоровье), Objective (тип цели, количество, лимит времени),
  Spawn (тип объекта, позиция, количество, скорость, урон),
  Rule (событие -> действие с задержкой);
- метод normalize() — обязательная нормализация недоверенного ответа LLM:
  зажимает числа в безопасные диапазоны, заменяет мусор значениями по умолчанию,
  выбрасывает неподдерживаемые типы объектов/правил, ограничивает размеры списков.


7. LLM\GameMode\GameModeSpecValidator.java
------------------------------------------
Валидатор спецификации. Проверяет GameModeSpec ДО нормализации,
чтобы отсеять мусорные ответы нейросети (например, пустой "{}").
- validate() возвращает список текстов ошибок; пустой список = спека валидна.
- Проверяет: непустое name, наличие секций world/player/objective,
  допустимые значения перечислений, диапазоны чисел (скорость, здоровье,
  лимит времени и др.), непустой список spawns, корректность позиций и правил.
- Пустое description допускается и затем заполняется в normalize().
- Для survive допускается targetCount=0; для collect требуется targetCount>=1.


8. LLM\GameMode\GameModeGenerator.java
--------------------------------------
Превращает текстовый запрос игрока в проверенный GameModeSpec.
- Хранит SYSTEM_PROMPT — жёсткую инструкцию для модели: возвращать только
  один валидный JSON по заданной схеме, без пояснений, markdown и лишних полей.
- buildChatPrompt() собирает промпт в чат-формате Phi-3/Phi-3.5
  (<|system|> ... <|user|> ... <|assistant|>).
- generate() делает максимум 2 попытки (MAX_ATTEMPTS = 2):
  запрос к LLM -> extractJson() -> парсинг Jackson -> валидация -> normalize().
  При ошибке отправляет модели предыдущий ответ, конкретную ошибку
  и исходный запрос с просьбой исправиться.
- extractJson() вырезает из сырого ответа ровно один сбалансированный
  JSON-объект: снимает markdown-обёртку ```, корректно считает вложенные
  фигурные скобки и учитывает строки/экранирование. Метод пока private,
  отдельного JsonExtractor нет.
- Полный rawResponse и извлечённый JSON сейчас выводятся в консоль.
- Если обе попытки провалились — бросает RuntimeException; fallback пока нет.


9. LLM\GameMode\GameModeApplier.java
------------------------------------
Применяет готовый GameModeSpec к игровой сцене.
- Все объекты режима вешаются на отдельный узел modeNode ("GeneratedMode").
- apply() сначала полностью очищает предыдущий режим (detachAllChildren),
  затем создаёт объекты по списку spawns: пока это кубы-заглушки 1x1x1 м
  с цветом по типу (враг — красный, предмет — зелёный, чекпоинт — бирюзовый,
  ловушка — оранжевый).
- Объекты внутри группы разводятся по позициям, чтобы не слипаться.
- Вызывать apply() можно только из главного потока обновления jME
  (Main делает это через enqueue()).
- Фактически применяет только spawns. world/player/objective/rules пока
  остаются данными и не создают игровую механику.
- Следующий шаг по развитию: игрок, цели, правила и cleanup механик.
  glTF/GLB отложены до стабильного MVP; файлов в src/main/resources сейчас нет.


КАК ФАЙЛЫ РАБОТАЮТ ВМЕСТЕ (краткая цепочка)
-------------------------------------------
Клавиша 1/2 в Main -> GameModeGenerator (промпт -> LocalLlmClient:
MockLocalLlm или OnnxGenAiPhiClient) -> сырой JSON -> Jackson -> GameModeSpec
-> GameModeSpecValidator (проверка) -> GameModeSpec.normalize()
-> GameModeApplier.apply() (объекты на сцене, только в render-потоке jME).
OnnxSmokeTest стоит отдельно и служит только для проверки реальной модели.
